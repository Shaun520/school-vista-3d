## 1. 项目现状

- 已有可交互单文件原型 [prototype.html](./智慧校园3D平台_原型资料/prototype.html)（187KB / 2037 行），覆盖顶部 6 个导航、右侧 5 类面板、天气与时间、4 路模拟监控、POI、楼层拆解、第三人称与 AI 本地模拟。
- 原型的定位是**交互与视觉参考**，不是最终技术栈。最终路线已确定为 React + React Three Fiber，三维资产按模块拆分 GLB（方案 B）。
- 室内采用**地点切换**：点击教室后切换到室内固定机位，不做连续行走、碰撞和物理模拟。
- 三个正式 GLB 已完成归一化、Meshopt 压缩和材质合并，可直接接入网页。
- 当前完成：布局冻结、Vite + React + TS + R3F 工程骨架、HUD 骨架、三个 GLB 的外景接入、相机预设、POI 标签与详情卡、加载进度、性能读数、无头浏览器验证。

当前主要缺口：

1. 地面、道路、绿化、校门仍为程序化占位，尚未形成统一风格的场地资产。
2. 教学楼楼层节点分组需要复核，当前 `FLOOR_01`–`FLOOR_06` 的包围盒互相重叠。
3. 操场 GLB 的法线贴图会导致草地渲染为黑色，目前用运行时 `stripNormalMaps` 规避，需在资产管线修复。
4. 室内场景、天气与昼夜、监控流、数据面板、AI BFF 尚未接入。
5. 真实数据源、外部 API Key、视频流和素材版权尚未确认。

## 2. 资产实测

实测工具：[tools/asset-pipeline/measure.mjs](../tools/asset-pipeline/measure.mjs)，执行 `npm run measure`，加 `-- --meshes` 可输出逐网格包围盒。

| 资产 | 文件 | 体积 | 包围盒（m） | 三角面 | 材质 / 贴图 | draw call |
| --- | --- | --- | --- | --- | --- | --- |
| 教学楼群 | `public/assets/campus/teachBuilding.glb` | 2.42MB | 125.17 × 18.74 × 116.05 | 122,136 | 17 / 9 | 78 |
| 操场 | `public/assets/campus/playground.glb` | 4.18MB | 188.39 × 4.01 × 100.90 | 43,290 | 12 / 16 | 12 |
| 教室 | `public/assets/interior/classroom.glb` | 9.68MB | 10.96 × 3.32 × 7.48 | 92,722 | 50 / 44 | 58 |

外景合计：6.60MB / 16.5 万三角面 / 90 draw call，低于“桌面 1080p、35 万面 / 150 draw call”的预算。

### 2.1 实测发现

1. **`POI_*` 锚点全部在原点。** `POI_Teaching`、`POI_Playground`、`POI_Classroom` 都是无子几何的空节点，位置为 `(0,0,0)`，不能直接作为标签定位。当前 POI 位置由 `layout.json` 的显式坐标提供；后续应在 Blender 导出时把锚点放到实际位置。
2. **楼层分组包围盒重叠。** `FLOOR_01` 的 Y 范围是 0.24–3.54，`FLOOR_02` 是 0.28–10.79，`FLOOR_03` 是 0–17.17，`FLOOR_04` 是 0.28–18.74。说明部分高层物体被分到了低层组，直接按组做垂直位移会出现楼层穿插。楼层拆解前必须重新按楼栋 / 楼层分组。
3. **操场法线贴图异常。** 草地的 `normalTexture` 会让整块场地渲染为纯黑；移除法线贴图后草地恢复正常。当前在 `layout.json` 中用 `stripNormalMaps: true` 规避，正式做法是在 GLB 管线里删除或重建法线贴图。
4. **操场是裁剪版。** 只保留草地、局部跑道 / 铺地和少量看台构件，没有完整跑道线和看台；前端可按需补画跑道线。
5. **教室材质偏多。** 50 种材质、44 张图，首次进入可能出现 shader 编译卡顿；后续需要合并材质或做图集。
6. **三个源资产使用不同单位。** 教学楼 ×2、操场 ×0.5、教室 ×0.2 已完成归一化，最终 GLB 统一为 1 单位 = 1 米、Y 轴向上、地面 y = 0。

## 3. 核心技术栈

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 构建 / 语言 | Vite + React + TypeScript strict | 纯 SPA，构建快，类型约束 3D 节点与状态 |
| 3D 渲染 | three + `@react-three/fiber` + `@react-three/drei` | 与 React 组件化一致，drei 提供相机、HTML 标签、加载器 |
| 资产管线 | Blender + glTF 2.0 + gltf-transform + Meshopt | 已实测，教学楼 draw call 从 4339 降到 78 |
| 状态管理 | Zustand | 单 store 管 tab、天气、时间、相机、POI，避免每帧 setState |
| UI | CSS Modules + CSS Variables | HUD 斜切、描边、发光定制强，1920×1080 舞台等比缩放 |
| 图表 | ECharts | 替代 Unity XCharts，暗色青绿主题可统一 |
| 相机 / 动画 | CameraControls + GSAP | 监控机位、楼层展开、室内切换的平滑过渡 |
| 视频 | hls.js / flv.js + VideoTexture | HLS / FLV 拉流，面板 video + 场景内贴图 |
| 服务端 | Node + Hono/Express，SSE | DeepSeek、高德 Key 只放服务端 |
| 测试 | Playwright / puppeteer-core | 关键交互回归、截图对比、控制台检查 |
| 部署 | 静态托管 + Serverless/Node | GLB 走对象存储 / CDN，开启 br 压缩 |

### 3.1 选型取舍

- **不用 Next.js**：没有 SSR 需求，3D 首屏用加载态控制更直接。
- **不用物理引擎**：室内为地点切换，不做碰撞和行走模拟。
- **不用单一全场景 GLB**：无法分包、无法单独替换建筑、POI 与楼层拆解不灵活。
- **不依赖运行时 CDN**：依赖全部本地打包，避免网络不可达；版本在初始化时锁定并提交 lockfile。
- **不手绘 3D 中国地图**：生源地图涉及标准地图合规，优先 ECharts 标准底图或省份排行视图。

## 4. 架构

```text
Blender 源资产
  └─ 导出 / 减面 / 贴图降采样 / Meshopt
       └─ public/assets/campus + interior
            └─ src/data/layout.json
                 └─ React + R3F 浏览器运行时
                      ├─ 3D 场景：GLB、相机、天气、POI、楼层
                      ├─ HUD：React DOM 覆盖层、ECharts、视频面板
                      └─ Zustand Store
                           └─ Node BFF
                                ├─ /api/chat   → DeepSeek（SSE）
                                ├─ /api/weather → 高德
                                └─ 视频流鉴权 / 代理
```

三层边界：

- **资产层**只负责产出可加载的 GLB 和布局约定，不包含业务逻辑。
- **浏览器运行时**负责渲染、交互、HUD 和状态，不直接持有外部 API Key。
- **BFF** 负责密钥、限流、超时、缓存和降级，前端只调用同域接口。

## 5. 布局冻结 v1

### 5.1 坐标系

- 1 单位 = 1 米，Y 轴向上，地面 `y = 0`。
- 校园范围：X `-83 … 224`，Z `-156 … 155`，约 **307 × 311m**。
- 地面基准网格 600 × 600m，外围再铺 1600 × 1600m 暗色底板。

### 5.2 摆放

| 对象 | 中心位置 | 尺寸（m） | 说明 |
| --- | --- | --- | --- |
| 教学楼群 | `(0, 0, -78)` | 125.17 × 18.74 × 116.05 | 北侧主建筑群，朝向暂定 0° |
| 操场 | `(110, 0, 55)` | 188.39 × 4.01 × 100.90 | 东南侧，长轴东西向 |
| 中心广场 | `(0, 0, -2)` | 半径 14 | 教学楼与操场之间的集散区 |
| 校门 | `(0, 0, 132)` | 22 × 6.5 × 2.5 | 南侧主入口，程序化占位 |
| 主路 | 中心 `(0, 0.02, 64)` | 14 × 136 | 校门 → 广场 |
| 横向路 | 中心 `(75, 0.02, 0)` | 280 × 10 | 广场 → 操场北侧 |

几何关系：

- 教学楼南边界 `z = -19.97`，操场北边界 `z = 4.55`，中间留出约 24.5m 广场带。
- 主路在 `x = 0`，操场西边界 `x = 15.8`，主路不穿过操场。
- 横向路与操场北边界有约 0.5m 重叠，后续补道路边线时再微调。

### 5.3 POI

| ID | 名称 | 位置 | 作用域 | 说明 |
| --- | --- | --- | --- | --- |

| `classroom` | 多媒体教室 | `(0, 3.4, 0)` | interior | 室内场景锚点 |

### 5.4 相机预设

| ID | 位置 | 目标 | 用途 |
| --- | --- | --- | --- |
| `home` | `(185, 135, 220)` | `(50, 2, -8)` | 全局鸟瞰 |
| `teaching` | `(78, 34, 28)` | `(0, 8, -78)` | 教学楼近景 |
| `playground` | `(110, 62, 178)` | `(110, 0, 55)` | 操场近景 |
| `gate` | `(0, 12, 162)` | `(0, 4, 95)` | 校门与主路 |
| `plaza` | `(0, 16, 55)` | `(0, 4, -8)` | 广场与教学楼入口 |

### 5.5 室内

- 教室 GLB 自动居中 XZ、贴地。
- 固定机位：`entry = (0, 1.6, 6.2)`，`lookAt = (0, 1.4, 0)`。
- 室内资产按需加载，退出时恢复室外相机状态；不对室内做碰撞和行走。

### 5.6 冻结规则

1. 布局只改 `src/data/layout.json`，不在组件里写死坐标。
2. 模型默认自动居中 XZ、贴地；确需保留原点时关闭 `centerXZ` / `snapToGround`。
3. 楼体是否投影由 `castShadow` 控制；操场目前关闭投影以控制 draw call。
4. 操场 `stripNormalMaps` 是临时规避，资产管线修复后删除该标记。
5. 新增建筑或场地时，先补 `layout.json` 条目，再补模型文件，最后更新本节表格。

## 6. 工程骨架

### 6.1 已实现

- Vite + React 19 + TypeScript strict + three / R3F / drei。
- 1920×1080 等比舞台，按视口缩放并居中，1366×768 无溢出。
- 顶部导航 6 项切换、左侧图标工具栏、右侧数据面板、实时时钟与天气占位。
- 三个 GLB 接入：Meshopt 解码、自动居中 / 贴地、阴影控制、包围盒归一化。
- 程序化地面、道路、广场、校门占位。
- POI 标签、详情卡、5 个相机预设、加载进度、性能读数 `DRAW / TRI / TEX`。

- `npm run verify:ui` 无头浏览器验证：截图、控制台错误、导航 / 相机 / POI 交互、1366 溢出检查。

1. 固化资产管线：把 `.workbuddy` 中的临时脚本迁到 `tools/asset-pipeline/`，加入减面、贴图降采样、材质合并、法线贴图修复、POI 锚点定位。
